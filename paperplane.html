關於我

自動化不該只活在
某個人的電腦裡

很多自動化只是「某個人電腦上的一支小程式」，那個人一請假或離職，就沒人會修。我想做的是團隊接得住的日常工具：大家看得到它在跑、出事會收到通知、壞了知道怎麼退回，接手的人也看得懂當初為什麼這樣做。

我是承育，有電商營運與後勤背景，現在是金車電商部的自動化工程師，這個職位是公司為了自動化新設的。

我的工作從坐到實際做事的同事旁邊開始：看他怎麼做、哪裡會出錯、出錯了誰會痛。接著拆成步驟、寫成規格，用 AI 協作寫出程式，經過兩輪審查、在測試環境驗證後才上線。

  • 需求 → 規格

    訪談第一線、拆成步驟，把「大家都這樣做」寫成可以驗收的規格。

  • 落地與維運

    用 Python、GAS（Google 試算表腳本）、VBA（Excel 巨集）串接公司系統與電商平台，放在公司內網伺服器常駐執行，上線後持續維護。

  • 風險控管

    先用測試帳號、上線前新舊結果逐一比對、隨時能切回人工作業。

CASE 01金車・2026.08 上線運作中

自建 API 上線：補上最後一哩路

問題
公司系統沒有開放程式寫入的入口，所以自動化做到最後一步，還是得靠人手動上傳。
做法
自己建一個接口（API），放在公司內網伺服器 24 小時待命，要有金鑰才能使用，讓程式直接寫入公司系統。
取捨
選擇放在公司內網、不放雲端：省下 VPN 申請與資安審查；代價是外面連不進來，伺服器也要自己維護。
成效
官網訂單、出貨轉業績兩條流程改由它處理，不需人工介入；上線前用 330 筆資料測試，零損壞。
自建 REST API · FastAPI · SQL Server · 金鑰驗證
CASE 02金車・2026.08 上線運作中

官網訂單全自動匯入

問題
每月約 40 批，每批要人工處理 20 分鐘；而且公司系統不讓我方刪除資料，匯錯了就收不回來。
做法
抓單 → 篩選 → 匯入 → 對帳 → 通知，全程按時間表自動跑；匯入這一步交給自建的 API。
取捨
先比對、再切換：新舊兩條路同時跑，4,095 格都一樣才切換（代價：晚一輪上線）；改一行設定就能退回人工。
成效
2026.08.05 起停用人工匯入，每一批自動對帳。
Python · 排程自動化 · 自動對帳 · 新舊並行比對
CASE 03金車・2026.08 起運作中

內網自動化控制台

問題
小程式都裝在各人電腦上，壞了要跑到座位旁處理，也看不到有沒有跑成功。
做法
把任務搬上公司內網伺服器，做成網頁控制台：依人授權、一鍵執行、自動留紀錄，急件推播到手機。
取捨
我推翻過自己的判斷：原以為訂單匯入失敗後會自己恢復，發現不會，就補上自動補匯。手機只推「卡住、等人處理」的急件。
成效
12 支任務、3 個組別使用；50 多條決策紀錄完整，換人也接得起來。
FastAPI · 帳號權限 · 排程整合 · Telegram Bot
CASE 04安永金融科技・2025 已交付

AI 名片識別系統

問題

CASE 05思博特・2021–2025 已交付

採購自動化閉環

問題
採購量靠人工估，旺季缺貨、淡季庫存積壓；國外廠商的在途（運送中）數量也看不到。
做法
串接 ERP（企業資源管理系統），依季節性因素自動算出建議採購量、一鍵下單；再用 GAS 把在途清單寫回，納入下一輪預測。
成效
採購評估時間縮短 90% 以上；在途數量即時可見；不需額外購買系統。
Ecount ERP API · GAS · Google Sheets · 預測模型
